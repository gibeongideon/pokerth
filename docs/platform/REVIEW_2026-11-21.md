# Production-readiness review — Phases 0–5 (2026-11-21)

Four independent reviews: money core, identity/access/social, tables + game server, player app.
Every finding was checked against the code before fixing. Status: `[x]` fixed in this pass,
`[~]` mitigated now / full fix scheduled (see the note), `[ ]` open.

## Critical
- [x] C1 **Missing `PLATFORM_ENV` = local mode in production** → dev routes (`/dev/token/<anyone>`), dev JWT secret accepted, no Secure cookies, public docs. *Fix:* env defaults to `prod`; dev routes need env=local **and** `PLATFORM_ENABLE_DEV_ROUTES=1`; secret guards for every non-local env.
- [x] C2 **Game deleted when every player is offline** (game server), then a reconnect creates a fresh game for the same table → the remaining player wins the pool by start timeout; a server restart resets running tournaments. *Fix:* never auto-remove a running platform game; never create a second game for a table that already had one.
- [x] C3 **Lost results keep escrow forever** (crash/restart/platform down > retry window; no admin path). *Fix:* results spooled to disk and retried after restart; running-table watchdog alert; audited admin *settle* / *void & refund*.

## High
- [x] H1 Withdrawal limits bypass: split + unconfirmed not counted + no lock; per-request auto-approve/KYC thresholds. *Fix:* count `awaiting_confirmation`, re-check under a per-user lock on confirm, rolling-24h thresholds, cap open unconfirmed withdrawals.
- [x] H2 Stale ORM rows under `FOR UPDATE` (expire_on_commit=False) → second transfer initiated. *Fix:* `populate_existing` on every lock.
- [x] H3 Admin `self_excluded` status not enforced. *Fix:* sets `excluded_until`; `is_excluded` honours the status.
- [x] H4 Sign-in code brute force (25+/email/h, racy limit, no per-IP). *Fix:* per-email daily failed-code cap, new link burns older ones, serialized + per-IP magic-link limits.
- [~] H5 Two tables on one game server → forfeits one (username = session identity). *Fix now:* `table.max_concurrent_per_user` = 1 (default). Multi-table per player: Phase 6 (sessions keyed by user+table).
- [x] H6 Open table that never fills locks buy-ins. *Fix:* pull out any time while open; auto-cancel + refund after `table.open_max_minutes`.
- [ ] H7 App: retried POST after token refresh always fails (consumed body). *Fix:* clone the request before sending.
- [ ] H8 App: action lost when the socket is closing (optimistic update, nothing sent). *Fix:* only act when sent.
